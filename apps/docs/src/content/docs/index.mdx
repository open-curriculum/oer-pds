## What is this?

**OER Design System** is a pedagogical design system for open education. It provides a shared vocabulary for describing, applying, adapting, validating, and automating instructional design decisions in open educational materials.

It is not a platform. It is a **reference library and vocabulary** — like a design token system, but for pedagogy instead of visual style.

## Core Design Principle

> **The OER Design System provides pedagogical "styles" for learning materials — not visual styles, but instructional styles.**

The same lesson content can be structured as direct instruction, a constructivist studio project, a mastery checkpoint pathway, or a critical media analysis exercise — using the **same content object**, different tokens and patterns.

## Relationship to OERSchema and AIUL

| Layer | What it describes |
|-------|------------------|
| **OERSchema** | What the learning resource *is* and how its educational parts relate |
| **AIUL** | Conditions under which AI use is permitted in a learning activity |
| **OER Design System** | How the learning experience is pedagogically structured, styled, adapted, and validated |

The OER Design System sits beside OERSchema as a pedagogical design layer, and treats AIUL as one token family (`aiUse.*`) within the broader system.

## Machine-Readable Files

AI agents and automation tools can discover and apply this system through static files:

| File | Purpose |
|------|---------|
| [`llms.txt`](llms.txt) | LLM discovery and operating rules |
| [`llms-full.txt`](llms-full.txt) | Full specification for AI agents |
| [`ois-index.json`](ois-index.json) | Normalized registry of all tokens, patterns, themes, renderers, and validation rules |
| [`ois-context.jsonld`](ois-context.jsonld) | JSON-LD context for the OER Design System vocabulary |

JSON Schemas for each object type are available at [`schemas/`](schemas/).
